# Java 代码风格与扩展约束

这是本项目的长期约束，跨会话继续开发时优先遵循本文件。

## 语法边界

- 使用 Java 8 风格的普通 class、interface、enum、集合和异常处理。
- 不使用 `record`、`sealed interface`、`var`、模式匹配、`getFirst/getLast`、文本块等较新的语法/API。
- 不为了“新写法”牺牲读者对对象生命周期、字段含义和控制流的理解。
- 运行时 JDK 由 Spring Boot/Alibaba 版本最低要求决定；运行时版本不等于源码必须使用该版本的新语法。

## 注释要求

- 每个类写清职责、拥有的状态、协作对象和不负责的事情。
- 每个类属性写清含义、单位、允许为空的条件、生命周期和线程/调用边界。
- 每个公开方法和关键私有方法写清输入、输出、状态变化、异常/失败行为和幂等性。
- 关键算法逐步写中文注释，说明为什么先做这一步、边界在哪里、结果如何被后续使用。
- 注释解释设计原因和业务语义，不重复 `if` 或方法名本身。
- RAG 解析、切分、Embedding 批处理、混合召回、重排、引用校验、预算扣减和上下文压缩必须有算法注释。

## 可扩展设计

- **策略模式**：切分策略、数据 Provider、检索融合、重试和上下文压缩策略。
- **适配器模式**：Qdrant、SimpleVectorStore、Elasticsearch、pgvector、模型 Provider。
- **工厂/注册表模式**：根据 `ModelProfile`、RAG profile 和 `DataMode` 创建实现。
- **模板方法/流水线**：文档导入、角色报告和研究阶段共享固定步骤，具体 provider 只实现差异点。
- **组合优先**：Agent 组合 Gateway、Policy 和 Tool，而不是继承具体 SDK 客户端。
- **依赖倒置**：领域与 Graph 不依赖数据库、HTTP 客户端、Qdrant SDK 或模型 SDK。
- 新增后端优先新增实现类和配置；只有公共语义改变时才修改核心接口。

## 代码审阅检查

每个阶段检查：是否出现禁用语法；类/属性/方法/关键算法是否有中文注释；核心类是否依赖具体 provider；错误、超时、取消和预算是否有明确行为；接口是否能够替换实现；测试是否覆盖正常路径和至少一个失败路径。
