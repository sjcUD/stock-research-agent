# 模块对应的 Agent 知识与学习完成标准

本文件补充产品功能与实施计划，说明读者通过每个模块能理解什么机制、为什么需要它，以及如何验证理解。**这是学习目标规划，不代表模块已实现或课程正文已完成。** 拟新增 Java 文件只作为未来阅读入口；现阶段可阅读的固定版本参考源码见[研究证据](README.md#源码证据)。

## 已确定的框架学习主线

用户已选择Spring AI Alibaba Agent/Graph。通过业务逐步学习：Spring AI模型/工具契约 → Alibaba ReactAgent → Graph状态/节点/条件边 → 顺序/并行/路由组合 → 检查点与人工中断/恢复。每项能力以R0及对应阶段的真实验证为准；不把框架选择记录为模块已实现。

| 模块 | 要学习的框架机制 | 应证明的边界 |
| --- | --- | --- |
| M01 | ReactAgent工具循环、模型/工具拦截、结构化结果 | 框架执行循环，业务仍校验权限与父预算 |
| M03 | Graph状态、节点、条件边与输出合并 | 固定研究工作流不冒充模型动态规划 |
| M04 | Graph检查点、持久化适配、中断与恢复 | 图状态不等于产品run状态，SSE回放不等于崩溃恢复 |
| M07 | 人工确认与Graph中断/恢复连接 | 检查点不会替代owner/参数哈希/过期/幂等校验 |
| M08 | 顺序、并行、路由等Agent组合与子图 | 每角色独立上下文、父预算和取消仍需验证 |
| M09 | 运行时上下文和模型/工具拦截 | 结果引用与配方不能突破原有工具权限 |

框架主线只选择Alibaba；LangGraph4j可作后续对照阅读，不加入产品依赖。具体API以锁定发布tag源码为准，避免将main上的功能提前计入课程。

## 学习主线与先修关系

贯穿案例：“比较三家公司的现金流 → 查财报解释差异 → 保存研究 → 结合持仓继续分析 → 跟踪新披露”。从一次请求的生命周期逐层展开，避免把学习变成框架 API 和目录浏览。

先理解五个基础概念：**消息**承载用户/模型/工具的交互；**上下文**是本次模型实际看到的内容；**工具调用**是模型提出的结构化动作意图；**运行状态**由程序记录执行进展；**证据**是结论关联的原始数据或文档。保存过的聊天不一定在当前上下文中，提出工具意图不等于工具已经执行。

建议学习顺序：M01 模型与工具 → M02 数据契约 → M03 连续研究 → M04 任务生命周期 → M14 Harness加固 → M05 结果展示 → M06 文档证据 → M07 操作确认 → M08 多 Agent → M09 上下文与结果引用 → M10 个人上下文 → M11 持续跟踪 → M12 系统评测。M13贯穿每次交付。工程实现顺序仍以实施计划为准，例如任务系统应早于前端完整交付。

区分两类知识：工具调用、上下文、检索增强、规划/编排、多 Agent、记忆、人工介入和评测属于 Agent 主线；身份解析、数值计算、数据库事务、事件回放、调度、前端状态属于支撑这些机制可靠工作的工程知识。后者不会因为加上“Agent”名称就变成模型能力。

## 各模块的学习任务

### M01：模型的动作意图如何变成一次真实工具调用？

- **先修：** HTTP请求/响应、JSON、普通Java接口；定义模型消息、toolCallId、工具schema和工具结果。
- **机制：** 模型输出结构化意图 → 框架解析 → 应用校验权限/预算 → 工具执行 → 结果回填 → 模型继续或结束。Spring AI提供模型/工具契约，Alibaba ReactAgent推进循环，应用拦截器仍决定是否允许外部动作。
- **验证：** stub模型请求一次数据工具，观察相同callId的结果回填；将预算限制为2次模型请求，第3次必须在发出前停止。
- **拟阅读入口：** `runtime/FrameworkAgentConfiguration.java`、`runtime/RunBudget.java`。应能解释“框架接管循环”为什么不等于“框架承担全部权限与可靠性”。

### M02：为什么工具返回的不能只是一段看起来正确的文字？

- **先修：** M01；证券身份、金额/单位、来源与截止时间。
- **机制：** 解析证券 → 选择有能力的provider → 获取带日期的快照 → 规范化单位 → 返回结构数据/证据/缺口，供模型观察。计算由Java执行，模型组织解释。
- **验证：** 同名输入触发澄清；研究日之后披露的财报被拒绝；缺价格返回不可用，不能变成0或模型猜价。
- **拟阅读入口：** `instrument/InstrumentResolver.java`、`marketdata/MarketDataProvider.java`、`marketdata/AsOfPolicy.java`。这部分主要建立可信工具边界，不把抓接口等同Agent智能。

### M03：连续追问如何修改当前研究，而不误用旧上下文？

- **先修：** M01/M02；上下文与持久历史的区别，实体选择和研究日期。
- **机制：** 新输入与当前选择集 → 识别意图/歧义 → 明确ResearchRequest → 执行研究阶段 → 更新可追问状态。固定阶段通过Alibaba Graph节点与条件边安排，阶段内ReactAgent可以选择受控工具；讲清状态写入与输出合并。
- **验证：** 从三家公司比较追问“只看前两家”，随后“换成近三年”，观察工具参数保留正确标的并只修改周期；多个候选时不得猜测。
- **拟阅读入口：** `research/ConversationContext.java`、`research/ResearchWorkflow.java`。区分预设Workflow与模型动态规划；首版实现前者与有限工具自治，不声称具备通用自主规划。

### M04：一次研究为什么必须独立于聊天连接存在？

- **先修：** M01/M03；run与会话区别、持久状态、事件序号和终态。
- **机制：** 提问创建持久run → worker执行 → 保存Graph检查点与产品事件 → SSE只是订阅；恢复只复用身份/版本/数据指纹一致的已完成阶段。
- **验证：** 刷新后继续看到同一run；取消后不再启动工具；JVM中断后显示INTERRUPTED，显式恢复产生关联新run；重复请求不重复研究。
- **拟阅读入口：** `runtime/ResearchRunService.java`、`RunWorker.java`、`RunEventStore.java`。模型消息记忆与业务检查点不同，不能把恢复理解为重新发送最后一句话。

### M05：模型回答、图表和执行进度如何保持一致？

- **先修：** M01/M02/M04；结构化输出、metricId/evidenceId与toolCallId。
- **机制：** 工具产生结构数据 → 产物校验 → 保存版本 → 前端按schema渲染；模型只写说明与引用。事件负责表达已执行的行为，不从“正在查询”等回答文字推断进度。
- **验证：** 同名工具并发仍按callId正确结束；事件重放不重复消息；改写回答措辞不能改变图表数值；缺引用的关键数值不能发布。
- **拟阅读入口：** `artifact/ArtifactValidator.java`、`evidence/MetricRefValidator.java`、前端`reduceRunEvent`。UI组件渲染是产品工程，模型提出组件意图也不获得执行任意代码的权限。

### M06：怎样让财报中的一段材料支撑一句结论？

- **先修：** M02/M05；文档/页/片段、词法与语义检索、向量相似度。
- **机制：** 解析/切分 → 带元数据索引 → 按标的/空间/时间检索 → 组合上下文 → 模型回答 → 引用与关键数值校验 → 回到原文。Embedding命中代表相似性，不代表事实证明。
- **验证：** 两家公司的相似段落不串；未来披露材料不进入历史研究；引用存在但不支持数字时降为待验证；缺材料时明确说明不足。
- **拟阅读入口：** `document/DocumentRetriever.java`、`document/DocumentChunker.java`、`evidence/ClaimEvidenceValidator.java`。OCR、复杂表格抽取等未交付能力不计入已学内容。

### M07：模型提出“加入关注”后，系统还缺少什么授权？

- **先修：** M01/M04/M05；只读/写入、提案与实际副作用、owner与幂等。
- **机制：** 形成动作与参数 → 保存待确认提案 → 用户核对 → 校验owner/参数哈希/时效 → 原子消费 → 恢复已中断的图分支 → 写入一次。报告档案保存研究产物，不自动成为注入模型的经验。
- **验证：** 同一确认重复点击只保存一次；批准后修改股票代码会被拒；过期提案不能执行；打开旧报告不调用模型重新生成。
- **拟阅读入口：** `identity/ActionProposalService.java`、`artifact/ArtifactVersionService.java`。人工介入应讲清“批准的是哪次动作与哪些参数”，不能只展示一个确认按钮。

### M08：为什么要拆成多个Agent，它们怎样合作？

- **先修：** M01/M03/M04/M05；角色输入输出、父任务预算、并行与汇总。
- **机制：** 分配基本面/市场/新闻任务 → 每角色独立上下文与工具集 → Alibaba并行组合/Graph子图产出报告/证据 → 汇总冲突与缺口 → 发布。固定角色编排不等于模型自动发现组织结构。
- **验证：** 检查每角色实际输入，看不到另一角色原始对话；一个超时仍保留其他证据；所有子任务共享总预算；比较单Agent与多Agent的事实/引用/成本差异。
- **拟阅读入口：** `research/roles/RoleExecutor.java`、`research/ParallelResearchStage.java`、`research/ReportSynthesizer.java`。多轮辩论与多数票不能替代独立证据验证；A2A协议后置。

### M09：上下文有限，如何继续使用大结果和更多工具？

- **先修：** M01/M03/M05；token估计、结果存储、引用与schema校验。
- **机制：** 完整结果留在受控存储，模型接收摘要/resultId → 下一工具按受限路径读取 → 校验owner/run → 继续计算；压缩对话保留实体/时间/引用。
- **验证：** 大序列不完整塞入prompt也能计算；跨run/owner引用被拒；压缩后“前两家”仍正确。若后来引入工具目录，未加载schema与未获执行权限必须分别处理。
- **拟阅读入口：** `runtime/ToolResultStore.java`、`runtime/ContextPolicy.java`、`research/ScreeningCriteria.java`。Skill是研究配方，只有未来实现目录/配方执行后才可计为实践完成；基础压缩已前置到M14/H1，Task9扩展结果引用与工具选择，不把R1的保护拖后。

### M10：了解我的持仓，是否就等于Agent拥有长期记忆？

- **先修：** M02/M03/M07；业务快照、用户偏好、会话摘要与经验的区别。
- **机制：** 导入预览/确认 → 保存不可变持仓事实 → 按任务读取最新有效快照 → 计算权重/覆盖 → 仅注入必要信息；偏好由用户显式编辑。
- **验证：** 100万与1万的两项持仓按市值而非条目数计算；缺行情不输出完整组合判断；更新偏好只影响后续研究，不修改历史产物；未经批准经验不注入。
- **拟阅读入口：** `portfolio/PortfolioSnapshot.java`、`PortfolioCalculator.java`、`identity/UserPreferenceService.java`。数据库里有历史记录不代表模型实际使用了记忆；向量经验召回不是此模块默认已实现能力。

### M11：Agent如何持续执行已经授权的研究任务？

- **先修：** M04/M07/M10；跟踪对象、触发条件、调度与变更基线。
- **机制：** 用户确认跟踪范围 → 调度或新披露触发 → 创建带上下文的run → 取新证据/比较版本 → 有变化才站内通知；失败与无变化是不同状态。
- **验证：** 重启后任务保留；多个worker不重复执行；同一披露不重复通知；未变化时保持安静；暂停后不启动新任务。
- **拟阅读入口：** `tracking/TrackingScheduler.java`、`ChangeDetector.java`、`NotificationService.java`。触发由程序与数据事件控制，不把定时扫描描述为模型一直在自主思考。

### M12：怎样证明Agent做对了，而不只是说得像？

- **先修：** M01—M09；固定输入/期望、证据、执行轨迹、基准与时点。
- **机制：** 固定数据和配置 → 执行同一任务 → 确定性检查身份/数字/时间/权限/引用 → 抽样评价解释 → 比较单/多Agent或新旧版本 → 记录成本。模型判官只辅助评价文本。
- **验证：** 流畅但数字错误的回答仍失败；引用对不上时仍失败；未来信息被拒；换模型后能复跑相同案例；资金回测另有现金/成交/费用账本。
- **拟阅读入口：** `evaluation/AgentEvaluationRunner.java`、`eval/equity/cases/v1.json`。Agent任务质量、程序执行正确性、投资策略收益是三个不同结论；不存在一个收益数字证明全部机制正确。

### M13：读者如何通过一份真实交付串起前述机制？

- **先修：** 已交付阶段的机制，不提前要求后续模块。
- **机制：** 固定版本、问题与输入快照 → 跟踪请求/工具/阶段/证据/产物 → 解释一个设计取舍和一个失败边界 → 在同版本复现。
- **验证：** 读者能说出谁做决策、谁执行、状态归谁、何时停止；能定位结果证据，并区分设计目标与已实现行为。不是仅完成启动截图。
- **拟阅读入口：** `docs/equity/stages/R*/README.md`、`docs/equity/source-map.md`、阶段验收记录。该模块是学习交付，不另造一个Agent算法；文章按任务因果关系组织，模块目录仅供定位。

### M14：如何让每次模型和工具调用在边界内推进？

- **先修：** M01—M04的调用、状态、观察与持久任务；不用先掌握多Agent。
- **机制：** H01按调用生命周期组织拦截链、短路与失败收尾；H02原子父预算/单次超时/取消；H03分类重试、参数修正、部分结果和检查点恢复；H04外置/裁剪/摘要并校验上下文保真。基础放R0/R1，多Agent和持续任务继承同一治理。
- **验证：** 两子任务不能花同一份最后配额；重试与摘要都计费；401不反复重试；超时不编造数据；压缩后“前两家”、asOf、确认状态与证据引用不变。
- **拟阅读入口：** `runtime/harness/`、Alibaba固定版ModelInterceptor/ToolInterceptor/MessagesModelHook；旧基金P2的策略与测试作对照，不复制其手写循环。实现与先修问题详见[Harness学习单元](07-harness-design-and-learning.md)。
