## 三、三个完整场景

### 场景 A：从一句话到可追问的比较

“比较贵州茅台、五粮液和泸州老窖，重点看现金流和估值。”

解析身份与比较日期→检查字段/供应商能力→取同口径数据→Java 计算→证据校验→比较表/趋势图→保留引用的说明→“只比较前两家”接续执行。未得到新闻不阻断已有财务结果；不能将未查新闻写成“近期无负面事件”。

### 场景 B：从报告结论回到原始文档

“经营现金流改善的原因是什么？”

定位已选公司的材料→检索对应报告期/披露时点→提取页码证据→对照数值→标出事实、假设、缺口→点击 [1] 打开原文页→继续提问→保存新报告版本。没有支持时显示“现有材料无法解释”，不以通用财务常识补成该公司的事实。

### 场景 C：结合持仓持续研究

导入 CSV→展示单位/标的/重复项/缺价格→确认保存快照→按市值检查集中度→报告覆盖率→提出跟踪方案→确认创建站内复盘→定时任务比较新旧快照与材料→有变化时通知。模型不能把分析结果直接变为券商订单。

## 四、学习与公众号内容对应

| 章节组 | 用户看到的增量 | 核心问题 | 可观察证据 |
| --- | --- | --- | --- |
| L0 工具与模型边界 | 单股问答可查数据 | 模型为什么不能直接给行情？工具意图由谁执行？ | 工具参数、证券身份、日期与结构结果 |
| L1 连续研究 | 同业比较与追问 | 如何把“前两家”解析为当前选择，而不猜上下文？ | 会话状态与工具调用轨迹 |
| L2 证据研究 | 财报问答与来源回跳 | 检索命中为何不代表答案得到支持？ | 页码、claim-evidence、数值验证 |
| L3 可靠任务 | 刷新续看、停止和恢复 | 流式连接为何不能代表任务生命周期？ | 事件序号、终态、租约与阶段检查点 |
| L4 多 Agent | 三维研究与汇总 | 多角色在什么时候增加证据，而不只增加成本？ | 单 Agent 对照、上下文隔离、共享预算 |
| L5 个人上下文 | 自选、持仓与偏好 | 聊天记录、业务事实、偏好、经验分别属于谁？ | 快照、确认、owner 与注入记录 |
| L6 长期执行 | 定期复盘和变化提醒 | 如何让调度、去重和恢复在无人盯着时可靠？ | executionKey、claim、变更与通知记录 |
| L7 评测 | 固定快照与历史实验 | 回答质量、运行正确性和策略结果如何分别验证？ | 可复现数据集与三类独立评分 |

每阶段至少交付：运行说明、源码阅读图、固定数据示例、失败场景、验收记录、对应文章。本文只是课程对应计划，没有生成课程正文。手写基金循环作为作者个人原理材料，公开产品主线已确定采用Spring AI Alibaba Agent/Graph，并逐步讲解ReactAgent、图状态/节点/条件边、组合Agent、检查点和人工中断/恢复。

## 五、Harness能力与学习前置

四项能力不是界面菜单，而是F09/F15/F16及所有研究调用的公共底座：

| 能力 | 首次交付 | 学习与验收 |

| 上下文压缩 | R1基础、R3扩展 | 结果外置、完整组裁剪、摘要与保护状态；追问对象/证据不漂移 |

详见[Harness加固设计与学习](07-harness-design-and-learning.md)，参考基金P2、Claude官方资料/独立第三方研究与DeepSeek公开实现。公开产品仍采用Alibaba框架。

## 六、版本边界

R1 是能真实完成研究任务的第一版，不承诺组合、自动跟踪和资金回测同时完成。设计 UI 展示整体产品方向，各阶段只开放已交付入口。实盘交易、任意代码沙箱、分布式 A2A、全量估值模型、自动因子训练、自动经验自进化均列为独立后续议题，不默认纳入本轮路线。

模块的先修、机制、验证场景与拟源码入口见[模块学习地图](05-agent-learning-map.md)。功能交付与学习完成分别记录，不把规划视为已学会。
